# bugtongPH — Authority & Project Identity

## Purpose

This file defines the project-level rules and source precedence for bugtongPH.

## Authoritative layers

1. **Notion `bugtongPH Riddle Database`**
   - riddle identity
   - stored wording
   - answer
   - source/metadata
   - usage status

2. **Active Character + Art Style + Voice pair**
   - character identity
   - appearance
   - reference assets
   - art/material language
   - scale conventions
   - voice/speech identity

3. **Approved PLOT**
   - story
   - environment
   - physical states
   - dialogue
   - speakers
   - timing
   - feasibility

4. **Validated RENDER**
   - current Clip 1 pose/state
   - camera composition
   - environment
   - lighting
   - current visual progression

5. **`active-pair-runtime.md`**
   - parameterizes legacy hard-coded references so they use the active pair

6. **Veo / Google Flow references**
   - provider-oriented prompt construction
   - camera
   - motion
   - dialogue
   - audio
   - timing
   - feasibility

7. **DRAFTS**
   - performance planning only

## Project identity

Each episode is one setting + one believable situation + one active character pair + one database-backed bugtong.

The project should feel coherent within the selected pair and art direction. New pairs are allowed, but they must remain isolated from legacy or other pairs.

## Core continuity principle

A later stage may refine execution but may not silently rewrite a higher-priority source.
